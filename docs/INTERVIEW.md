# 面试与简历说明

## 可核实的简历表述

**RouteCast 路由链路负载预测与调度原型｜个人项目**

- 使用 PyTorch 实现膨胀时序卷积与链路图聚合，对多链路遥测进行六步负载预测；按时间切分数据并以训练集参数标准化，完成时序模型消融、持久性及周期基线对比。
- 实现容量预留、业务竞争分配与切换惩罚的路径规划器，提供 Prometheus/SNMP 导出转换、FastAPI 拓扑演示及 ONNX 推理导出；固定种子模拟测试中预测 MAE 为 0.0325，较持久性基线下降约 44.6%。

数字必须连同“模拟测试”一起写。不写真实网络吞吐提升、生产上线或用户规模。

## 面试必须讲清楚

1. 为什么用链路图？预测目标在接口 / 链路层，共享节点意味着潜在流量相关；当前邻接只是一种结构先验。
2. 为什么训练标准化不能用全量？测试期统计量会泄漏未来；验证 / 测试的输入可使用此前已发生的历史，但目标必须完全落在各自时段。
3. 图聚合是不是通用 GNN？当前是固定归一化邻接的邻域混合，不是注意力图网络，也不支持无验证地更换拓扑。
4. 为什么不能宣称最优路由？多业务按带宽排序贪心，可能错过全局更优组合；容量由预测而非真值约束，还会有预测失误。
5. 调度有什么代价？回放中超限次数下降，但接纳少一次、路径切换更多，切换惩罚需业务验证。
6. 如何上线？先影子模式接入真实遥测，连续回测；再包级仿真，最后才设计带回滚的控制面，不直接连接生产路由器试验。

建议阅读顺序：`data.py → model.py → train.py → routing.py → benchmark.py → api.py`。独立改一次预测窗口、增加一个容量竞争测试，并解释实验变化后再把该项目写为熟练掌握。
